### C. Gateway installer/upgrader audit

Full report: `/root/installer-gateway-audit.md`

Key outstanding findings (analysis only, no fixes applied):

1. Offline bundle gateway package is stale/incomplete — no Dockerfile or image tar for fresh local-gateway provisioning.
2. `safe-upgrade.sh` never installs/refreshes the local Docker gateway, its env, or `/etc/sokrat/local-gateway-hook.json`.
3. Existing gateway images are reused without rebuilding when the tag exists.
4. Native push is disabled before the Docker gateway health check; a failure leaves no push path.
5. Offline FCM default path is doubled (`installer-bundle/installer-bundle/...`).
6. `install-local-gateway.sh` hardcodes `FCM_ENABLED=true` even when no credential exists.
7. Offline gateway bundle still contains `.env` and `config/firebase-service-account.b64`; treat the key as exposed.
8. Local PBX seed uses `apiURL: http://127.0.0.1:8095/`; the PBX API is `8080`.
9. frpc unit is create-only, so existing installs never receive `Restart=always`.
10. `safe-upgrade.sh` does not back up local gateway state directories.

Local runtime observation from the audit:

- `sokrat-gateway-local` container was up, but `sokrat-gateway-control` and the push child were FATAL.
- `18080/health` returned 502 and `8095` was closed.
- Logs showed `Cannot find module './push-errors'`.
- This may be a local test artifact, but it demonstrates the one-shot health-check limitation.
